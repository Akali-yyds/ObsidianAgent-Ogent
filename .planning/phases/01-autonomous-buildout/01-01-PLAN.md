<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| chat view → agent runtime | Untrusted user prompts and session history enter the execution loop |
| agent runtime → model provider | Vault-derived context and tool specs leave the local plugin process |
| model provider → tool executor | Untrusted model tool-call arguments cross into local tool execution |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01-01 | T | `src/agents/agent.ts` tool dispatch | mitigate | Preserve `validateArgs()` before every tool run and keep unknown-tool handling explicit rather than dispatching by unchecked name |
| T-01-01-02 | D | `src/agents/agent.ts` loop execution | mitigate | Keep existing `maxSteps` cap and `runWithTimeout()` enforcement so the refactor cannot create unbounded tool loops |
| T-01-01-03 | E | `src/agents/agent.ts` consent boundary | mitigate | Preserve the current consent gate for mutating tools and stop execution after denied consent exactly as the legacy loop does |
</threat_model>
