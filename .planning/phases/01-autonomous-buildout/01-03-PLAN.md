<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pack JSON on disk → runtime loader | User-editable configuration enters trusted execution |
| vault note contents → retrieval/verifier pipeline | Local note text becomes model input and quote-match source |
| verifier model output → claim state | Untrusted model judgment influences support status but not quote presence |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03-01 | T | `src/packs/loader.ts` | mitigate | Validate every pack file against strict schema rules and reject missing provider/model references instead of defaulting silently |
| T-01-03-02 | I | `src/packs/defaults/*.json` and runtime allowlists | mitigate | Keep the bundled grounded-research pack on read-only tools only so the happy path cannot trigger write consent or mutate vault data |
| T-01-03-03 | T | `src/agents/quote-match.ts` | mitigate | Derive `quote_present` from whitespace-normalized code-level matching against live note text, not verifier-model output |
| T-01-03-04 | R | `src/agents/verifier.ts` | mitigate | Persist source note path, quote text, and support rationale fields so UI and later evals can trace each verification decision |
</threat_model>
