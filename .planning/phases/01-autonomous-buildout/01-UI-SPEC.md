# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — imperative Obsidian `createEl` UI in `src/view.ts` |
| Icon library | Obsidian core icons where already available; simple text glyph fallbacks are acceptable in Phase 1 |
| Font | Obsidian theme UI font via existing `var(--font-ui-*)` tokens |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Badge inset, inline icon gap, compact separators |
| sm | 8px | Row gaps inside header controls and claim metadata |
| md | 16px | Default control spacing and card internals |
| lg | 24px | Vertical separation between result sections |
| xl | 32px | Separation between transcript blocks in long verifier results |
| 2xl | 48px | Not used as a new Phase 1 default; reserve for major empty states |
| 3xl | 64px | Not used in Phase 1 |

Exceptions: icon-only controls may render at 28x28px on desktop to match current header density; any mobile-tappable control added in Phase 1 must expose a 44x44px hit target.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background-primary)` | Root view, transcript, composer, expanded claim details |
| Secondary (30%) | `var(--background-secondary)` | Turn cards, sessions panel, pack summary surface, progress container |
| Accent (10%) | `var(--interactive-accent)` | Selected pack state, active progress step, source-note links, in-app recovery CTA |
| Destructive | `var(--text-error)` | Fatal pack/config/runtime errors only |

Accent reserved for: active pack indicator, running-step marker, note-opening links/buttons, and the recovery action that returns a blocked session to Classic mode. Do not use accent to color every badge or every header control.

## Locked Decisions Applied

- Pack choice is session-scoped, defaults to Classic, affects future turns only, and restores on reopen. Source: `01-CONTEXT.md` D-01 to D-04.
- Pack mode replaces the editable single-model control with read-only pack/provider/model information, fails loudly on missing provider/model config, and offers in-app recovery back to Classic or another pack. Source: `01-CONTEXT.md` D-05 to D-08.
- Verified-only summary sits above a separate flagged-claims section. Green requires quote present + support. Unsupported quote-present claims stay visibly explained. If nothing verifies, render a failure-style result with no clean summary. Source: `01-CONTEXT.md` D-13 to D-16.
- Unsupported multi-agent packs are hidden on mobile. Source: `REQUIREMENTS.md` PACK-05, `ROADMAP.md` Phase 1 success criteria, `PROJECT.md` Constraints.

## Phase 1 Surface Contract

| Surface | Contract |
|---------|----------|
| Header mode control | Add a session-level selector in the existing header area. Label it `Mode`. Desktop options: `Classic`, `Grounded Research`, plus any other supported packs. Keep it in the chat panel, not settings. |
| Classic model control | When `Mode = Classic`, keep the current editable model input and current session-model behavior. No new copy or validation changes beyond existing configured-state handling. |
| Pack summary header | When a pack is active, replace the editable model input with a read-only summary block: first line = pack name, second line = `Retriever`, `Synthesizer`, `Verifier` model attribution in compact text. Do not show a disabled text input. |
| Pack scope hint | Under the pack summary, show one muted sentence: `Applies to future turns in this chat.` |
| Progress rendering | Pack runs render a compact 3-step stack at the top of the active assistant turn: `Retrieving notes`, `Drafting claims`, `Verifying claims`. States: pending, running, complete, failed. No percent bars and no separate side panel. |
| Structured-output retry status | If structured output retries once, show a muted inline sub-row under the active step: `Retrying structured output (1/1)…`. If retry fails, pin the step to failed and show the pack error copy in the same assistant turn. |
| Verified summary block | After a successful pack run, render `Verified summary` as prose/markdown containing only verified claims. Never include flagged claims in this block. |
| Flagged claims block | Render a separate section titled `Flagged claims` for unsupported or missing-citation claims. If no claims verify, replace the verified summary block with a failure-style heading `Verification failed` and the sentence `No claims could be verified against your notes.` |
| Claim card | Each claim renders as a bordered card with: state badge, claim text, source note button/link, disclosure toggle, and details area. Verified cards default collapsed. Unsupported and missing-citation cards default expanded on first render. |
| Source evidence details | Expanded details must show the quoted text when present. Unsupported cards must also show a short verifier explanation inline without requiring another click. Missing-citation cards replace the quote with `Quoted text not found in the live note.` |
| Source-note navigation | Every claim card includes a single explicit action labeled `Open source note`. It opens the cited Obsidian note in the workspace. Label text should use the note basename; full path can appear as muted secondary text or tooltip. |
| Model attribution footer | Every pack result ends with a muted footer line: `Models used: Retriever — {model}; Synthesizer — {model}; Verifier — {model}`. Classic runs do not add this footer. |
| Misconfigured pack recovery | A pack config failure renders an error banner in the assistant turn and shows two recovery actions in the header region: `Use Classic mode` and `Choose another pack`. No silent fallback. |
| Mobile-safe gating | On mobile, hide unsupported multi-agent packs from the selector. If a session already has an unsupported pack selected, hide pack options, disable send for that session, and show a non-crashing banner: `Grounded Research is available on desktop only for now.` with a single CTA `Use Classic mode`. |

## Interaction Rules

1. New sessions open in `Classic` mode and preserve the current single-agent UX until the user opts into a pack.
2. Changing the header mode affects future turns only. Existing turns retain the mode they were created with.
3. Returning from pack mode to Classic restores that session’s last classic model value.
4. Pack selection is never per-message and never global.
5. The pack selector must not appear in plugin settings; Phase 1 pack choice lives in the chat panel only.
6. Keep all new pack UI inside the existing `src/view.ts` header/transcript layout. No modal-based verifier drilldown and no new pane.
7. Source-note actions must resolve to Obsidian files only; no external URLs.
8. Claim disclosure labels are `Show details` and `Hide details`.
9. Claim badges use exactly these labels:
   - Verified: `Verified`
   - Quote present but unsupported: `Unsupported`
   - Quote missing: `Quote missing`
10. Step state treatment:
    - pending = muted label only
    - running = accent marker + active label
    - complete = success treatment
    - failed = destructive treatment with inline reason below the failed step

---

## Data and Rendering Constraints

- Fit the contract into the current imperative DOM architecture in `src/view.ts`; prefer extending the existing header and assistant-turn renderer over introducing a new view framework.
- Session persistence must absorb `selectedPackId` plus the session’s last classic model value; this is required by D-01 through D-08.
- Classic assistant turns may remain plain text/markdown. Pack assistant turns may add structured metadata for progress, claims, and attribution, but must still degrade safely inside the existing transcript list.
- Progress updates should reuse the current event-driven rendering cadence; do not introduce a second async polling loop for UI-only state.
- Phase 1 does not include pack authoring, advanced filtering controls, confidence meters, or alternate orchestration visuals.
