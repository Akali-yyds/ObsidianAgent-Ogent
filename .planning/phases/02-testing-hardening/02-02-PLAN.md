<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| fixture vault/query corpus → eval runner | Untrusted fixture content is parsed and scored by the CLI harness |
| CLI harness → runtime seam | Non-UI callers invoke grounded-research logic without the full Obsidian environment |
| runtime results → report files | Generated eval summaries must reflect actual claim buckets without omission or distortion |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05 | T | `hackathon/eval/fixtures/queries.json` | mitigate | Validate query structure and category coverage before execution so malformed or incomplete fixture data cannot skew results silently. |
| T-02-06 | R | `hackathon/eval/run.ts` | mitigate | Write JSON source-of-truth reports with per-query and per-claim fields so markdown summaries can be traced back to raw output. |
| T-02-07 | E | `src/packs/runtime.ts` / `src/packs/vault-adapter.ts` | mitigate | Keep eval on a narrow adapter seam so CLI callers cannot bypass pack validation or execute arbitrary Obsidian behaviors. |
| T-02-08 | D | `package.json` / `hackathon/eval/run.ts` | mitigate | Fail clearly on missing fixtures, bad output directories, or invalid runtime inputs instead of generating partial or misleading reports. |
</threat_model>
